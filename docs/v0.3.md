# v0.3 · 账单与实际支出

本轮在本地账本中加入账单确认、历史支出与价格生效日期，沿用 Electron、React、Ant Design 和 SQLite。

## 使用方式

- 扣款日生成待确认账单。在总览直接确认或跳过，也可以进入订阅详情操作。
- 确认时填写实际金额、币种与支付日期；例如美元订阅可记录银行卡实际扣款的人民币金额。
- 详情默认显示账单记录及按原币分别统计的累计实际支出；后续三期与变更记录在相邻页签。
- 已支付可以修改或撤销；已跳过可以恢复为待确认或记录支付。补录可以记录应用启用前的支付，同一应扣日期已有有效账单时请编辑现有记录。
- 调价请用详情的“调整价格”，填写今天或未来的生效日期。相同生效日期再次保存会替换该日期的计划，操作记录保留。
- 总览依次显示本月实际支出、月均订阅费用（附年度折算）与未来 30 天预计扣款。分类可切换月均预计 / 本月实际，下方显示近六个月实际支出。
- 日历按应扣日期显示预计、待确认、已支付、已跳过；已生成账单替代对应预测，不重复显示。日历独立按账单金额的币种筛选，跳过的金额不计入合计。

## 统计与生成规则

1. 实际支出仅包含已支付账单，按实际支付日期归属月份。未记录月份显示“暂无记录”，不把缺失记录推断为零支出。
2. 已支付账单保存原币、实际金额和确认时的完整参考汇率快照。历史统计使用自己的快照，不受后续刷新影响；编辑支付保留已有快照，原来缺少快照时保存会尝试补齐当前汇率。
3. 汇率获取沿用固定公共接口、日缓存、失败冷却和 8 秒超时；失败仍允许确认支付。涉及缺失汇率的完整总额显示“—”及缺失笔数，可编辑支付记录后补齐参考汇率或填写实际银行扣款金额。补录采用录入时参考汇率，并不提供历史日汇率查询。
4. 未来 30 天包含今天至今天 + 29 天。已支付或跳过的当期账单不重复进入预计扣款；待确认采用生成时金额。月均和年度折算采用今天生效的价格，未来预测根据每个应扣日选取生效价格。
5. 关闭续费或归档停止后续生成，保留已有账单及实际支出。变更前先补齐旧规则截至当天的账单；重新启用续费不追补关闭期间的账单。
6. 到期生成使用原始计费基准日，月底取当月最后一天，闰年恢复原日。应用启动加载、运行每分钟和系统恢复时补齐遗漏；订阅 ID 与应扣日期有唯一索引，重复启动不会生成重复周期账单。
7. 手动补录、支付日期不能晚于今天。已生成账单在修改价格、周期、名称或分类后保留生成时金额、币种与分类。实际服务商扣款仍需用户核实与确认。

## 升级、存储与恢复

- SQLite `user_version` 升至 3，新增 `bills`、`prices`、`billing_tracking`、`ledger_changes` 和递增的 `ledger_events`。
- 旧库先通过 SQLite `VACUUM INTO` 在数据库同目录生成 `xuding.db.pre-v3-时间戳.db` 一致性快照，再事务迁移；快照失败会停止升级。快照保留供手动恢复，不参与自动备份清理。
- 旧订阅保留原信息与初始价格，从升级当天开始跟踪，不自动推断之前的支付。新订阅从创建当天开始跟踪。旧版本不能直接打开新版数据库。
- 备份格式升级至 v2，包含订阅、账单、价格计划、账单跟踪进度和账单操作记录（含支付汇率快照）。应用偏好、订阅编辑审计、提醒去重与全局汇率缓存仍不随 JSON 导出。
- 继续接受 v1 备份。导入旧版备份时保留已有账单和价格历史，导入的订阅价格从当前日期记录；新增订阅从导入当天跟踪。
- v2 按订阅 ID 合并，同 ID 订阅及其账单、价格、操作记录、跟踪进度恢复至备份状态，未包含订阅完整保留。确认前展示账单与价格数量，恢复前保存安全快照。
- 订阅 / 账单 / 价格任何变更都改变账本修订号，过期预览不能直接覆盖后续编辑。外键、重复记录、生效日期与跨订阅 ID 冲突会在验证或事务中拒绝。
- 文件上限 50 MB，订阅上限 10,000；v2 备份需要 v0.3 或更高版本恢复。
